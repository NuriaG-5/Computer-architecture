# Design Report – MIPS Pipelined Processor with MMIO PWM Control

## 1. Introduction

This project implements a 5-stage pipelined MIPS processor with Memory-Mapped I/O (MMIO) support and a PWM peripheral. The goal is to demonstrate how a processor can interact with hardware peripherals through memory-mapped registers. The system reads the value of external switches and uses that value to control the duty cycle of a PWM signal generated by dedicated hardware.

The processor follows the classic MIPS pipeline consisting of Instruction Fetch (IF), Instruction Decode (ID), Execute (EX), Memory Access (MEM), and Write Back (WB) stages.

## 3. MMIO Design

### Address Map

| Address | Device                  | Direction  | Notes                        |
| ------- | ----------------------- | ---------- | ---------------------------- |
| 0x90    | Switches                | Read Only  | Returns current switch value |
| 0x98    | PWM Duty Cycle Register | Write Only | Sets PWM duty cycle          |
| 0x9C    | PWM Enable Register     | Write Only | Enables PWM output           |

### Address Decoding

The MMIO logic is implemented inside the data_memory module. During memory accesses, the address is compared against predefined MMIO locations. If the address matches an MMIO register, the corresponding peripheral is accessed. Otherwise, the access is directed to the internal RAM.

Example:

```verilog
case(addr)
    32'h00000090: read_data = {24'b0, switches};
    32'h00000098: read_data = {24'b0, pwm_duty};
    32'h0000009C: read_data = {31'b0, pwm_en};
    default:      read_data = ram_out;
endcase
```

### Read and Write Strategy

Writes are implemented synchronously using the clock edge. This guarantees predictable updates and matches the behavior of real hardware registers.

Reads are implemented combinationally so that the processor can obtain data immediately without waiting for an additional clock cycle.

## 4. PWM Controller Design

The PWM peripheral uses a simple counter-comparator architecture.

### Architecture

```text
Duty Cycle Register
        |
        v
   Comparator <------ Counter
        |
        v
     pwm_out
```

The controller contains an 8-bit counter that continuously increments from 0 to 255.

The output is generated according to:

```text
pwm_out = 1 when counter < duty_cycle
pwm_out = 0 otherwise
```

### Duty Cycle Mapping

| Duty Register | Duty Cycle |
| ------------- | ---------- |
| 0x00          | 0%         |
| 0x40          | 25%        |
| 0x80          | 50%        |
| 0xC0          | 75%        |
| 0xFF          | ~100%      |

### PWM Frequency

The PWM period is determined by the 8-bit counter.

```text
PWM Period = 256 × Tclk
```

For a clock period of 10 ns:

```text
PWM Period = 256 × 10 ns
           = 2560 ns
```

## 5. Software Algorithm

### Selected Profile

Profile B was selected because it demonstrates continuous interaction between the processor and a hardware peripheral through MMIO.

### Algorithm

The processor continuously reads the switch value and updates the PWM duty-cycle register.

### Pseudocode

```text
Enable PWM

while(true)
{
    duty = ReadSwitches()
    WritePWMDuty(duty)
}
```

### MIPS Program

```assembly
addi $t0, $zero, 1
sw   $t0, 156($zero)

loop:
lw   $t1, 144($zero)
sw   $t1, 152($zero)
j    loop
```

This program continuously updates the PWM duty cycle whenever the switch value changes.

## 6. Reflection

One challenge was integrating the MMIO registers into the existing pipelined processor while ensuring that memory accesses continued to operate correctly. Debugging the interaction between the pipeline and the peripheral registers required careful waveform analysis using GTKWave.

If more time were available, the project could be extended with additional peripherals such as LEDs, timers, or motor-control interfaces. Support for interrupts would also improve the interaction between software and hardware devices.
